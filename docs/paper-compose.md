# Typst recomposition adapter candidate

`composeDocument` accepts a `falsify.paper-document.v1` model, source bytes, exact edits and an injected compiler. It verifies the source SHA-256, binds each edit to a unique block, page and UTF-16 range with matching before text, builds fixed Typst source using string literals, and returns actual PDF bytes, SHA-256, warnings and unavailable mappings. It does not mutate the model. `compileInWorker` terminates its owned worker on completion or abort; an arbitrary injected compiler cannot be interrupted by this adapter, though cancellation is checked before and after it.

The adapter snapshots the model, edits, source bytes and compiler result for one attempt. It inserts spaces at observed line boundaries when neither neighboring character is whitespace, except after a literal hard hyphen; it preserves that hyphen without adding an internal word space. It uses the first page size, a fixed two-column layout and an optional supplied font family. The host must provide compiler and font bytes explicitly. The font coverage hook `fonts.hasGlyph(codepoint)` can report missing characters; when absent or failing coverage is unavailable.

An optional `outputCheck` receives copied actual PDF bytes and the logical expected blocks. A content mismatch remains a finding and the real draft stays downloadable. A text-check pass sets `contentVerified` for that logical text comparison only; it does not verify visual appearance, glyph visibility or assets. Without a checker, text verification is unavailable. These rules apply equally to edited and unedited calls.

Images, vector artwork, formula and table assets are not placed; image blocks without source ranges are retained as unsupported findings, not treated as preserved. Styles, captions, reading order, links, page and block destination mappings, full source font recovery and real-paper fidelity are not established. This is a development candidate, not a production or default engine. The browser test uses a locally supplied Arial font only; it is not redistributed here.

## Focused proof

Run `node --test app/tests/paper-compose.spec.mjs`. The synthetic browser harness in `app/tests/recomposition-compose/` expects the S0 Typst 0.7.0 scratch package and font at `../typesetter/.local/spike`, starts with `python app/tests/recomposition-compose/server.py`, and writes only `.local/compose-proof/output.pdf`. Open `http://127.0.0.1:18766/app/tests/recomposition-compose/index.html`; `?supported=1` excludes the deliberately unsupported scalar for a positive text control. The harness is local evidence, not application integration.

On 2026-10-27 a browser compiled a 22,020-byte PDF (SHA-256 `09d75952bc5047019be554a5cf25689f8409a6fb95eeec4c1206de228bf6b09d`). Independent PyMuPDF extraction retained literal `#import`, quotes, backslash, minus, citation and Ω, but U+10FFFF became NUL. Font coverage and output-text verification were unavailable in that run, and the candidate returned a warning with `contentVerified: false`. A downloadable PDF is therefore not evidence of text preservation.

After wiring the byte checker, the unsupported-scalar run returned an actual content finding (`bc54cf79be1a0625d9bac33f8e14b0ac42aaa5d1782c06011b4aef16615dde4a`, 22,020 bytes). The supported-character control returned text-check pass (`de78a2afff8231b7ad458df7e0067692de134e7fdb4c2d2e72b9d71a31b3fe55`, 22,024 bytes); PyMuPDF reread the literals, minus, citation and Ω. The coordinator recovered the interrupted worker's patch, ran nine unit tests and these actual browser checks. These are handcrafted text cases; the deliberately present image marker is not placed and the report retains that asset warning.
