# Source-bound paper document candidate

`readDocument({file, fileHash, signal})` accepts a `Uint8Array`, `{bytes: Uint8Array}`, or a File-like object with `arrayBuffer()`. It reads at most 25 MiB, computes SHA-256 over the actual bytes and rejects a supplied mismatching digest with `code: 'stale-source'`. `fileHash` is optional, case-insensitive hexadecimal. A pre-aborted signal, an abort during file loading, or an abort observed while extracting/between pages rejects with `name: 'AbortError'`, `code: 'aborted'`. Extraction within one synchronous MuPDF walk cannot receive an event-loop abort until it yields. The source is never changed. The module imports the existing pinned `mupdf` 1.28.1; it requires the same bundling/loader treatment as other bare-import app sources and is not wired into the UI.

`normalizeDocument({sourceSha256, pages, signal})` is a synchronous, testable adapter for observations, not a PDF parser. `sourceSha256` is lowercase 64-hex. `pages` is an array in source page order; each is `{width,height,blocks,images}` with positive dimensions, `blocks: [{bbox,chars: [{text,bbox,fontName,size,color}]}]`, and `images: [{bbox}]`. Boxes are `[left,top,right,bottom]` in the caller's observed frame, or null if unavailable. The caller is responsible for observations and their source binding. This function does not verify that observations came from the hash.

Output uses `falsify.paper-document.v1` and the shared `pages`, `blocks`, `styles`, `assets`, `relations`, and `diagnostics` fields. `pages[].text` is the concatenation of the reader's characters in its block order, with no added separators. Each block's `source.range` and character `start`/`end` are half-open UTF-16 offsets into that page text, not PDF byte offsets or global document offsets. Character bboxes and observed style IDs are retained. Text, including whitespace, digits and minus signs, is not rewritten. Block IDs bind source hash, page and range; repeated quotations on the same page are distinct. Style and image occurrence IDs are also source-bound. Image records represent observed locations only; they contain no image bytes and do not establish caption relationships.

Blocks correspond to MuPDF structured text blocks and use `kind: 'paragraph'` as a contract-compatible placeholder, not a semantic classification. Mixed-style blocks have `styleId: null`, with per-character style IDs. Text may include spaces inferred by MuPDF and has no inserted line break between reader lines. `source.lines` is the ordered list of observed logical line boundaries for retypesetting: each line has a half-open `range` into the raw page text, `bbox`, `direction`, `writingMode`, and `baseline` containing the first and last observed character origins (or null for an empty line). Adjacent line ranges can meet at the same raw offset; the boundary is not a character and is not a logical-text offset. Consumers must choose how to handle each boundary explicitly, without assuming a space or removing a hard hyphen. No normalized logical string is created. Callers of `normalizeDocument` may supply line `start`/`end` as character-array indices plus these observations; absent lines produce `line-boundaries-unavailable`. Offsets identify this observed stream, not original PDF objects, bytes, glyph IDs, or reliable paragraph boundaries. MuPDF's extraction itself can omit or reinterpret glyphs; its JS walker uses `String.fromCharCode` for each returned rune. Fonts are observations (name, size, color), not reusable font data. Empty text is diagnosed; OCR is not performed. Vector drawings, tables, formulas, links, headers, footers and relationships are not recovered; `semantic-structure-unavailable` records this limitation. Image and text geometry cannot establish edit authority.

If all text blocks have geometry, exactly one empty page-wide vertical strip of at least max(12 points, 2.5% of page width), with at least two blocks on each side and vertically overlapping column extents, triggers left-column then right-column top-to-bottom ordering. The gutter is recorded in `pages[].columnGutter` and `reading-order-heuristic` marks every inferred column ordering. This is a geometric heuristic, not proof of semantic reading order; layouts with a spanning title, ambiguous gaps, missing boxes or fewer blocks retain reader order and record `reading-order-unresolved`. Asset order remains observed order. `readDocument` records `pages[].geometry` as `frame: 'mupdf-display'`, with the actual displayed bounds and MuPDF page transform, and `originalPageMapping: 'unverified'`; `original-page-geometry-unverified` prevents treating these boxes as exact original-page coordinates. The transform is observed, not a validated mapping contract. Nonzero displayed page origins are rejected. A rotated synthetic PDF demonstrates that the display frame changes, but rotation/crop mapping and real papers need further validation.

The local candidate tests use synthetic observations and synthetic real PDFs including a two-line mixed-style block and a rotated page read by pinned MuPDF. They do not establish real-paper extraction, complete asset preservation, independent verification, or a full round trip.
