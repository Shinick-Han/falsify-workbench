# Paper recomposition bridge

`prepare(request, options)` in `app/src/paper-recompose.mjs` reads a source PDF, binds enabled edits to source ranges, builds the paper flow, captures artwork, plans fonts, composes a PDF and checks the output. `request.file` accepts a File, Uint8Array or object containing Uint8Array `bytes`; `fileHash` is an optional SHA-256. `edits` is an array or a `falsify.paper-edits.v1` snapshot with `edits`, optional `fileHash` and `revision`. An explicit empty array produces a no-edit baseline. `signal` cancels the operation.

Each enabled edit requires `pageIndex`, `before` and `after`. Binding uses the ordered source flow and source line boundaries, collapsing whitespace while retaining literal source punctuation, including line-end hyphens. The supplied `after` is kept exactly. Source parts carry original block IDs, page offsets and text; the first receives the replacement and subsequent parts receive deletion. The returned `bindings` include the original request, concatenated raw `sourceBefore` and the individual parts. Segment identity and anchor bounding boxes narrow matches when supported by the source model. Missing, ambiguous and overlapping selections raise `source-binding` with a specific details code. Unproven differences remain unmatched.

`options.compile` supplies the Typst compiler function; `options.fonts` supplies immutable font candidates, and `options.pdfjs` and `options.mupdf` provide the output checker and font inspection engines. The return includes the generated `file`, actual `sha256`, `verification`, `revision`, `bindings`, `sourceBinding` and `sourceAssets` alongside compositor fields. Findings in a valid output remain available through verification and warnings; they do not suppress the file. The caller owns visual review and integration.
# Source spacing evidence

When PDF.js is supplied, the bridge reads the same source bytes and derives word-space offsets only for uniquely corresponding, geometrically compatible source lines. It retains the native text and UTF-16 offsets; the offsets describe a logical space immediately before a raw character. The hinted document is used for binding, flow, and composition. Missing PDF.js, an unknown page frame, differing characters or ambiguous geometry produce no hint. Line-end hyphens remain part of the source quote.

For a user-selected native source range, `request.bindings` may supply an array of `{id, sourceSha256, parts}` or `{index, sourceSha256, parts}`. `id` identifies a unique edit ID; `index` is the zero-based position in the original edit array, including disabled edits. Each ordered part is `{blockId, pageIndex, start, end, before}` using the original block ID, page index, absolute native UTF-16 offsets and exact raw text. Paper-edit `anchor.start` and `anchor.end` are segment-local and must not be used as these offsets. Both identifiers may be supplied when they agree. Disabled edits remain unselected.

The bridge checks the source hash, text and bounds, page, unique flow ownership, contiguous flow order, asset ownership and overlap. Invalid or stale explicit selections fail without falling back to quote matching. `bindings[].matchMethod` is `explicit-source` or `quote`; `before` and `request` retain the supplied edit, while `sourceBefore` and `parts` report the selected raw source. The exact `after` is applied once to the first part.
