# AI가 배치를 다듬는 PDF 편집

AI가 현재 LaTeX 소스와 PDF 페이지를 보고 배치 도구를 선택한다. 기존 PDF 편집·컴파일·렌더링·검사 기능을 사용하며, 원문과 사용자가 선택한 RED 변경을 유지한다.

## 사용 순서

1. 논문 PDF에서 LaTeX 기준본을 만든 뒤 편집하거나, 원래 LaTeX 소스를 연다.
2. 사용할 변경을 선택한다. PC의 Codex CLI에 로그인하고 companion을 연결한다.
3. 고급 AI 배치 항목에서 원하는 배치를 적고 시작한다.
4. AI가 소스 읽기, 배치 수정, PDF 생성, 검사, 페이지 렌더링을 실행한다. 도구 결과와 페이지 이미지는 다음 판단에 전달된다.
5. 후보 PDF를 확인하고 다운로드한다. BLUE에 보낼 때는 이 PDF만 전달한다.

기본 PDF 편집은 계속 사용할 수 있다. AI 실행은 시작 버튼으로 요청하며 기존 Codex 구독을 사용한다. API 키를 등록하는 과정은 추가하지 않는다.

## 역할과 기록

모델은 다음 도구와 인자를 선택한다. 앱은 도구를 실행하고 결과를 돌려준다. 배치 스킬은 프로젝트 전용 `falsify-paper-layout`이며 companion에도 동일한 파일을 포함한다.

| 도구 | 실행 내용 |
| --- | --- |
| `read_source` | 프로젝트의 LaTeX 소스를 읽는다. |
| `replace_source` | 배치 명령을 수정하고 내용 보존 여부를 확인한다. |
| `compile_pdf` | 현재 프로젝트를 기존 브라우저 컴파일러로 생성한다. |
| `inspect_pdf` | 생성한 PDF의 겹침·잘림 등을 검사한다. |
| `render_pages` | 요청한 쪽을 PNG로 렌더링해 모델에 제공한다. |
| `finish` | 현재 결과와 남은 사항을 반환한다. |

기록에는 실제 실행한 도구, 소스·PDF 식별자, 검사와 렌더링 범위가 남는다. 배치 수정은 논문의 과학적 주장·수치·인용이나 의도적으로 넣은 결함을 바꾸지 않는다. 모델이 내용 변경을 제안하면 해당 도구 실행을 거절하고 이유를 돌려준다.

## 실행 범위

현재 구현은 앱 도구 호출을 모델이 선택하는 방식이다. 기존 CLI의 임의 셸·파일 실행은 켜지 않는다. 각 모델 요청은 한 번만 전송하며 도구 반복 횟수에 한도가 있다. 중단하면 후속 요청과 결과 반영을 멈춘다. 이미 접수된 단일 CLI 호출은 서버에서 끝날 수 있다.

배치 검사는 관측한 범위만 보고한다. 컴파일 성공, 기하 검사, 모델의 시각 검토를 구분한다. 검사가 일부이거나 개선할 곳이 남아도 생성된 PDF를 받을 수 있다. 후보와 현재 편집본은 구분해 보관한다.

원본 PDF를 LaTeX로 복원하는 과정에서 표 구조나 캡션 연결이 유실된 경우에는 복원 단계 개선이 필요하다. 배치 에이전트의 완료 상태를 원논문 복원 완료로 해석하지 않는다.
