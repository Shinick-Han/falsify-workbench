# PDF 재조판 구현 상태

2026-10-27 · WorkBite T-0141 · 로컬 통합 `8894c17`.

문서 전체를 읽어 원문 범위와 편집을 연결하고, 본문·스타일·그림·표를 Typst로 다시 출력하는 경로를 구현했다. 실제 두 논문에서 PDF가 생성됐다. 현재 단계는 [구현 계획](pdf-recomposition-plan.md)의 S2·S3 검수다. 공개 웹과 설치본은 `0.2.0-alpha.18`을 사용한다.

## 구현한 기능

| 항목 | 현재 동작 |
| --- | --- |
| 원문과 흐름 | 원본 해시, UTF-16 문자·줄·스타일·위치를 유지한다. 다단 본문, 줄 중간 삽입, 제목, 캡션과 fragment를 흐름에 연결한다. |
| 기존 자산 | 떨어진 그림 패널·라벨, 벡터 표와 outline 서식을 묶어 배치한다. 캡처는 영역이 제한된 SVG 안의 216dpi PNG이며 마스크·투명도를 반영한다. |
| 글꼴과 스타일 | 실제 글꼴 바이트로 문자 지원과 대체를 결정하고 크기·굵기·이탤릭을 전달한다. 기준본과 수정본에 같은 글꼴을 사용한다. |
| 전체 조판 | 본문과 자산을 1단·2단에 배치한다. 그림 종횡비를 유지하고 긴 캡션을 다음 페이지에 이어간다. |
| 편집 연결 | 기존 snapshot·quote와 직접 선택한 native source parts를 받는다. 요청 Before, 실제 원문, 정확한 After와 적용 출처를 남긴다. |
| 추출 보완 | 독립 PDF.js 결과와 문자·위치가 맞는 줄에서 빠진 공백을 복구한다. Unicode를 읽을 수 없는 원본 글리프는 확인된 원형 SVG로 배치한다. |
| 출력 검사 | 실제 PDF 바이트의 내용·순서·대략적 범위를 다시 읽는다. 줄 끝 하이픈 공백은 native glyph 증거로 구분한다. |
| 링크 관계 | 원본 링크의 등장 위치·URI·본문 범위·내부 목적지를 읽는다. 출력 annotation 연결은 다음 단계다. |

반복 머리말·꼬리말 배치와 페이지를 넘는 전체 범위 매핑은 별도 검수 브랜치에서 진행한다. 원본 글꼴 family 복원, 각주·내부 링크와 출력 자산의 독립 검사도 남아 있다.

## 실제 출력

| 사례 | 원본 → 출력 | 실행 조건 |
| --- | --- | --- |
| 36쪽 논문 기준본 | 36 → 45쪽 | `f0c0e1c`, 변경 없음 |
| 7쪽·26쪽 수정 | 36 → 45쪽 | `f68a5ba`, 두 요청 After 그대로 적용 |
| 찬물 샤워 논문 기준본 | 15 → 17쪽 | `f0c0e1c`, 변경 없음 |
| 찬물 샤워 8개 수정 | 15 → 17쪽 | `445f51f`, quote 6개와 명시적 원문 선택 2개 |

로컬 브라우저의 실제 Typst WASM으로 생성한 뒤 PyMuPDF로 재읽기·렌더를 확인했다. 파일·해시·실행 조건은 비공개 검증 디렉터리의 PDF/JSON에 보관한다. 36쪽 사례는 그림 패널 묶음을 개선하면서 초기 71쪽에서 45쪽으로 줄었다.

출력에는 반복 머리말·쪽번호가 본문 중간에 남는 문제가 있고 내용 검사도 finding을 반환한다. 이 결과는 S2·S3 전체 보존 합격 전의 개발 산출물이다. 생성 파일은 검사 결과와 함께 반환한다.

문구만 입력하는 연결은 36쪽 사례 2/2, 찬물 샤워 6/8이다. 나머지 두 인용에는 원문 줄 끝 하이픈과 차이가 있다. 8개 수정 출력에서는 해당 원문 범위를 직접 지정하고 원래 Before와 After를 보존했다. 이 실행을 문구 자동 연결 8/8로 계산하지 않는다.

## 수정과 검수

독립 검수와 통합 검사에서 다음 결함을 재현해 수정했다.

- 보충 Unicode 손상, 입력 Buffer 공유와 비동기 중 편집 대상 변경.
- 그림 옆 본문까지 자산으로 묶어 정상적인 편집을 거절하던 문제.
- 줄·fragment 경계의 단어 붙음, 혼합 스타일과 긴 After 처리.
- 원본 이미지에 가려진 옛 날짜가 조판본에 다시 나타나던 문제.
- 실제 하이픈을 제거해 `re-sign`과 `resign`을 같은 대상으로 찾던 문제.
- 숫자 일부를 수정할 때 앞 부호까지 함께 선택하도록 요구하던 제한.
- 명시적 선택이 surrogate pair의 절반만 바꾸거나 File-like 버퍼의 후속 변경을 읽던 문제.

`445f51f`의 focused suite는 실제 원본 fixture를 포함해 **104개 통과, 0개 skip**이다. 후속 File-like 소유권 수정 후 bridge suite는 18개가 통과했다. source-links의 합성 실제 PDF 테스트도 정규 실행 목록에 연결해 재검증한다. 기존 앱 전체 `scripts/test.mjs`는 `f0c0e1c`에서 exit 0으로 완료했다.

글꼴 실증은 로컬 Noto Serif/Sans와 기존 Liberation을 사용한다. Noto의 OFL 라이선스와 고정 소스·해시는 검증 디렉터리에 보관했고 production vendor에는 아직 추가하지 않았다. 초기 합성 실증의 시스템 Arial은 로컬 검증용이었다.

## 다음 순서

1. 반복 머리말·꼬리말, 이어지는 본문과 inline 글리프의 실제 배치를 검증한다.
2. 블록 전체 범위와 링크 목적지를 새 페이지에 연결하고 출력 annotation을 확인한다.
3. 두 논문의 변경 없는 재출력과 실제 편집에서 내용·그림·표·캡션·참조 보존을 확인한다.
4. 기존 수동 편집·RED·외부 AI 입력을 같은 경로에 연결하고 미리보기·다운로드·기록의 파일 해시를 맞춘다.
5. 통과한 커밋에서 worker·글꼴·Typst 패키지, 라이선스·vendor manifest를 정리해 공개 경로를 전환한다.
