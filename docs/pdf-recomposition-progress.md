# PDF 재조판 구현 진행 상태

2026-10-27. 관련 작업 T-0141. [구현 계획](pdf-recomposition-plan.md)의 초기 엔진과 검증 기반을 로컬 개발 브랜치에 통합했다. 공개 웹과 설치본의 출력 경로는 교체하지 않았다. 실제 논문 전체 재조판과 7쪽 후보의 완성 PDF는 아직 통과하지 않았다.

## 구현과 검증

| 구성 | 현재 결과 |
| --- | --- |
| 문서 읽기 | 원본 해시와 연결된 문자·줄·스타일·이미지 등장 위치를 읽고 UTF-16 범위를 유지한다. 보충 유니코드 손상은 native JSON 대조로 수정했다. |
| 이미지 자산 | 각 등장 위치의 PNG·마스크·변환을 보존한다. 벡터 도형과 캡션 관계, 실제 출력 배치는 남아 있다. |
| 배치 후보 | 제목·캡션처럼 단을 가로지르는 밴드와 단 후보를 생성한다. 의미적 읽기 순서를 확정하는 기능은 아니다. |
| 조판 어댑터 | Typst.ts 0.7.0 브라우저 WASM에 문자 그대로 전달하고 정확한 선택 범위를 적용한다. 현재 고정 2단 본문 시제품이며 자산·원본 스타일을 배치하지 않는다. |
| 글꼴 계획 | 실제 글꼴 바이트를 MuPDF로 읽어 문자 지원과 fallback 후보를 확인한다. 줄바꿈 제어 문자와 누락 글자를 구분한다. 원본 폰트 복원·브라우저 등록·조판 연결은 남아 있다. |
| 출력 검사 | PDF.js가 실제 출력 바이트를 읽어 순서·문자·대략적 범위를 검사한다. 실패한 내용에서 부분 문자열만 찾아 위치가 확인됐다고 표시하지 않는다. |

다음 결함을 재현해 수정했다.

- MuPDF JS 문자 콜백이 보충 유니코드를 다른 문자로 바꾸던 문제.
- PDF 글자 조각 사이에 공백을 추가해 단어를 분리하던 검사 문제.
- 단 시작·끝 편집에서 단어가 붙거나 `−12`에 공백이 생기던 문제.
- Node Buffer의 공유 저장소 때문에 해시와 실제 파일 내용이 달라지던 문제.
- worker 전송 실패 시 종료와 이벤트 정리가 누락되던 문제.
- 글꼴 검사 중 변경된 입력 메타데이터를 읽거나 줄바꿈을 누락 글자로 판단하던 문제.

새 테스트 44개를 기존 앱 테스트 실행 목록에 포함했다. 원본 구조·배치 후보·검사 모듈과 조판부의 네 수정 사항은 별도 작업자가 검수했고, 조정자가 테스트를 재실행했다. 조판부 검수에서 지적한 callback 내부 assertion은 테스트 바깥으로 옮겨 검사 실패가 삼켜지지 않도록 했다.

## 실제 실행 증거

브라우저 조판기 실증은 합성 2단 문서를 4쪽으로 출력했고, PyMuPDF로 124개 순서 표식과 두 단을 확인했다. 이 실증의 글꼴은 로컬에서 제공한 Arial이며 저장소에 배포하지 않았다. [조판기 실증](recomposition-engine-spike.md)에 패키지·소스·WASM 출처를 기록했다.

생성 PDF에 출력 검사를 연결한 브라우저 대조 실험에서는 지원되는 문자·인용·마이너스·Ω가 텍스트 검사를 통과했다. 지원하지 않는 U+10FFFF가 NUL로 출력된 실험은 실제 내용 불일치로 검출했다. 이 대조 실험은 마지막 줄 경계 수정 전 실행했으며, 마지막 수정은 14개 테스트와 별도 재현 검수로 확인했다. 전체 논문이나 그림 보존 성공으로 계산하지 않는다.

실제 36쪽과 15쪽 논문은 로컬에서 읽기를 재검증했다. 배치 후보가 나온 페이지는 각각 4쪽과 1쪽이고 나머지 32쪽·14쪽은 미해결이다. 문자 목록 대조는 같은 엔진의 공백 제외 비교이며 원문 정보 전체 보존을 증명하지 않는다.

## 다음 구현 순서

1. 실제 논문의 본문·그림·표·캡션 관계와 읽기 순서를 복원한다. 현재 발생한 다중 gutter와 객체 겹침을 실제 사례로 해결한다.
2. 글꼴 계획을 조판기에 연결하고 기준본·수정본에 같은 글꼴과 자산 배치 정책을 적용한다. 벡터·마스크·링크 등 미지원 객체는 보존 경로를 확인한다.
3. 두 논문의 무편집 전체 재출력을 통과시킨다. 원본 내용과 자산이 보존된 뒤 7쪽·26쪽 후보와 찬물 샤워 8개 변경을 적용한다.
4. 기존 RED·수동 편집·미리보기·다운로드·기록에 연결하고 공개 경로를 전환한다.

검사 결과는 개발·배포 판단과 출력 기록에 사용한다. 생성된 PDF의 다운로드에 새 승인 절차를 추가하지 않는다. RED/BLUE/검수 분리, 원본 보존과 Confluence 저장 방식은 기존 계약을 따른다.
