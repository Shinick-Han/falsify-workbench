# Byte-backed font coverage plan

`createFontPlan({text, fonts}, {mupdf})` is an independent, asynchronous candidate API. Supply `text` as the union of the original and every edited comparison text, and reuse the resulting plan for both outputs. Each ordered font is `{id, family, bytes}`, with a unique nonempty ID, a nonempty host-provided family label, and an `ArrayBuffer` or `Uint8Array`. The family is a label for a downstream compositor, not evidence of font identity or style. No fonts are supplied or registered by this module.

The planner snapshots and validates every candidate ID and family and snapshots its bytes before asynchronous work, hashes them with SHA-256, creates a MuPDF buffer and font, checks each distinct glyph-bearing Unicode scalar with numeric `encodeCharacter`, then destroys both MuPDF resources. Invalid text scalars are rejected. Each candidate exposes `id`, `family`, `sha256`, `coverage` (`covered`, `missing`, or `unavailable` with `missing` and optional `detail`), `getBytes()` (a fresh snapshot copy, or null), and `hasGlyph(codepoint)`: true or false only for successfully checked scalars in the union; null for unknown or invalid inputs. Invalid bytes or parser errors produce unavailable coverage, never coverage inferred from a name or callback.

The result exposes `candidates` in input order, `codepoints` (including all requested scalars), `layoutControls` (distinct TAB, LF and CR scalars in text order), `selected` (the first single candidate covering the whole union, else null), `fallback` (one `{codepoint, kind, fontId, family}` per distinct scalar, in text order), `missing`, `status`, and `hasGlyph(codepoint)` with the same tri-state convention. Entries with `kind: 'layout-control'` have null font ID and family and are excluded from glyph coverage and missing; their `hasGlyph` result is null. All other entries have `kind: 'glyph'`, including unrecognized controls such as NUL, which are checked normally. If a single candidate covers all glyph-bearing characters, every glyph fallback entry selects it. Otherwise the first available candidate covering each scalar is used; an unresolved entry has null ID and family. Overall `covered` includes a fully resolved multi-font fallback, `missing` means a scalar is absent from all successfully examined fonts with no unknown candidate, and `unavailable` means unresolved coverage could be affected by an unavailable candidate or no candidates were supplied. `missing` lists unresolved scalars even when their ultimate coverage is unknown. The plan describes character-to-font choice, not shaping, line breaking, or glyph placement.

The pre-existing `inspectFonts(text, fonts)` callback API remains unchanged and is not byte-backed evidence. This planner is not wired to the compositor. Font bytes supplied by the host are not proof of the original PDF font resource's identity, subset coverage, or legal/technical ability to reuse a full original font. Source style matching, redistribution decisions, browser font registration, text shaping, and compositor integration remain separate work. The tests use installed `pdfjs-dist` standard fonts locally; consult its `LICENSE_LIBERATION` and `LICENSE_FOXIT` for those fixtures.
