# Falsify Workbench 0.2.0-alpha.78

코퍼스 명령은 비어 있지 않은 `--out`을 모두 `out_dir_not_empty`로 거절하고 종료 코드 3으로 끝냅니다. `render.py render`, `source_mutator.py build`, `falsify corpus build`, `falsify corpus mutate`, `pdf_twin.py make`, `pair_corpus.py build`가 같습니다. `pair_corpus`의 `output_not_empty`와 종료 코드 2는 더 이상 쓰지 않습니다.

`render.py`는 LaTeX를 조립한 뒤 벤더 `table_lint`를 실행하고, 그림을 그린 뒤 `pdflatex` 전에 `figure_lint`를 실행합니다. ERROR는 `table_lint` 또는 `figure_lint`로 종료 코드 3입니다. WARN은 `{lint, code, count}`로 모아 정상본 개수만 공개하고, 결함본 개수가 다르면 `sealed/`에만 둡니다. 현재 픽스처의 경고는 `no-label`, `no-metric-direction`, `no-pipeline-figure`뿐이며 거절하지 않습니다. 이 경고의 재현율과 거짓 양성은 측정하지 않았습니다.

`blue scan-workspace --argument-outline`과 MCP `includeArgumentOutline`은 순위가 매겨진 논문마다 짧은 조언용 논증 개요를 더합니다. 기본은 꺼져 있고, 신호, 점수, 순위, 플래그가 꺼진 캐시 키는 바뀌지 않습니다. 재현율과 거짓 양성은 측정하지 않았습니다.

합성 소스 사례를 쓰는 지침을 `.agents/skills/falsify-corpus-author/SKILL.md`에 넣었습니다. 저장소는 그 사례를 만들 때 모델을 호출하지 않으며, 문서의 명령은 도구 argparse와 맞춥니다. 새 사례의 판정 성능은 측정하지 않았습니다.

호스팅 증거 검사는 고정 15초 대신, 작업의 저장된 종료 상태를 네이티브 워커 제한 시간에서 뽑은 예산 동안 기다립니다. CPU를 가득 채운 상태에서 50회 돌렸을 때 실패는 0회였고 가장 긴 대기는 약 12초였습니다. 원래 실패는 재현하지 못했습니다. 모델 기반 탐지기는 실행하지 않았습니다.
